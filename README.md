# 五笔字型练习（wubi_prac）

一个零构建、纯静态的五笔字根 / 单字打字练习页面。**双击 `index.html` 即可使用**，无需安装依赖、无需启动服务。

内置 **86 版（1986）/ 98 版（1998）/ 新世纪版（2008）** 三个版本的字根键位表与单字编码库，可随时一键切换，选择自动记忆。

## 功能特性

- **三种练习模式**
  - 字根练习：给出一个字根，敲出它所在的键位；
  - 单字练习：给出一个汉字，依次敲出完整五笔编码（键位槽逐码回显）；
  - 文章练习：逐字敲出《古文观止》选篇——题目上方下拉列表选篇（篇名 · 作者），题目框多一行单行文章内容，以当前字为中心开窗显示（已敲字标绿、当前字高亮、标点等无编码字符淡化并自动跳过，不展示全文）；篇内全部汉字均可逐字敲码（字库外汉字由补充码表 codes.js 提供三版全码），选篇后从第一字开始。当前字敲对才能进入下一字，答错不弹讲解卡、也不揭示后续编码，错字母标红占位，下一键直接取代后继续输入，无需空格重敲。进入模式与篇末自动随机换篇，下拉列表旁的 ↺ 按钮可随时从本篇开头重来。
- **三版本切换**：顶部绿色按钮组切换 86版 / 98版 / 新世纪版，键位字根、助记口诀、单字编码随之整体切换，`localStorage` 记住上次选择。
- **可视化键盘**：真实 QWERTY 三行错位布局，五区配色（横/竖/撇/捺/折），键帽标注区位号；支持鼠标 / 触屏直接点按。
- **答错讲解卡**：字根 / 单字模式答错时展开讲解——应敲键位、键名、助记口诀、该键字根（单字模式另附正确编码，逐码详解；末码是否为识别码由字库 `id` 标志精确判定，识别码按「末笔×字型」单独解释，成字字根则按「报户口+首笔+次笔」说明），内容随当前版本变化；手机端以居中弹窗呈现，不占页面高度，点按任意处继续。文章练习模式不弹讲解卡、不揭示正确答案，错字母仅标红占位，由下一键取代后继续输入。
- **练习统计**：正确 / 错误 / 正确率 / 连击 / 最高连击，一键重置。
- **触屏与响应式**：窄屏下页面左右边距收窄至 4px（约原 1/4），宽度让给键盘；键盘等比撑满全宽（容器查询）；统计五格改等宽网格确保真机 360/375px 宽也单行不换行；反馈文案改为「点按继续」；页面采用安全居中（内容高于视口时自然滚动，顶部不被裁掉）。

## 快速开始

```text
双击 index.html        # 直接以 file:// 打开即可
# 或者起个本地服务：
python -m http.server 8000    # 访问 http://localhost:8000
# 增加练习文章：编辑 texts/ 下的文件，见「文章库与新增文章」
```

## 操作指南

| 操作 | 方式 |
| --- | --- |
| 切换练习模式 | 顶部「字根练习 / 单字练习 / 文章练习」按钮 |
| 切换五笔版本 | 顶部「86版 / 98版 / 新世纪版」按钮（绿色高亮） |
| 答题 | 直接敲物理键盘字母，或点按屏幕键帽（Z 键五笔未使用） |
| 答对 | 键帽闪绿，稍候自动进入下一题（文章模式立即进入下一字） |
| 选择文章 | 文章模式下用题目上方的下拉列表（旁有 ↺ 从本篇开头重新开始）；进入模式 / 篇末自动随机换篇 |
| 答错后继续 | 字根 / 单字：讲解卡展开，按 **空格 / 回车** 或点按题目区进入下一题；文章：无需任何按键，下一键直接取代错字母续输更正 |
| 清零统计 | 右上「重置统计」 |

## 数据与码表

### 内置数据

- `js/data/keys.js`：每个版本一张 25 键表（不含 Z），每键含 `键名 / 助记词 mn / 字根 roots`。三版助记词均取自公开教程并与字根分布互校。另提供 `charMap()`（单字 → 编码条目索引）与 `entryFor()`（文章模式逐字取码：练习字库优先，字库外的字查 `codes.js` 补充表，标点等无编码字符返回 null；随版本失效）。
- `js/data/chars.js`：由脚本生成的 `W.data.CHARS = { '86': […], '98': […], '06': […] }`，当前每版本收录 **211 个常用字**（含 25 个一级简码字，简码字按简码收录——三个版本的一级简码完全一致）。字集与顺序沿用旧 86 版字库。条目形如 `{c:'字',code:'编码'}`，带 `id:1` 后缀表示**末码为识别码**（非字根），教学卡据此对末码单独解释；识别码字数：86 版 123 / 98 版 127 / 新世纪版 126。
- `js/data/codes.js`：文章模式补充码表（★ 生成文件，勿手改），覆盖 12 篇正文中 211 字库之外的 **962 个汉字 × 三版本全码**，使选篇后从第一字开始逐字敲码；86 版取 CNMan「旧86」列，98 / 新世纪版经双源交叉验证 0 处不一致。
- `js/data/texts.js`：文章库（★ 生成文件，勿直接编辑），由 `tools/gen_texts.py` 从根目录 `texts/` 生成，每条 `{ name, text }`（《古文观止》选篇 + 篇名/作者），保留通行本原文（含标点）。篇内全部汉字均可逐字敲码，仅标点等无编码字符在练习时自动跳过（滚动条中淡化显示，不会被标成已敲绿字），三版共用同一份素材，切版本只换编码不换文章。新增 / 修改文章的方法见下文「文章库与新增文章」。

三个版本并不只是换个说法，编码实质不同，例如：

| 字 | 86 版 | 98 版 | 新世纪版 | 说明 |
| --- | --- | --- | --- | --- |
| 物 | TRQR | CQRT | TQRT | 「牛」86 在 R，98/新世纪移到 C |
| 特 | TRFF | CFFY | TFFY | 同上 |
| G 键助记 | 王旁青头戋（兼）五一 | 王旁青头五夫一 | 王旁青头五一提 | 字根与口诀均有增删 |

### 重新生成 chars.js

`chars.js` 是生成文件，**请勿手工增删条目**；调整字集后按以下流程再生成：

```bash
# 1. 修改字集：直接编辑 js/data/chars.js 中 '86' 数组
#    （脚本以现有 86 条目决定字集与顺序）
# 2. 放好三份码表后运行（任意 Python 3 均可；MSYS2 / Git Bash 环境）：
/c/msys64/usr/bin/python tools/parse_codes.py
# 3. 核对 tools/output/report.txt，确认无缺失 / 不一致后覆盖：
cp tools/output/chars_generated.js js/data/chars.js

# 文章补充码表 codes.js（字集从文章库自动提取，改 texts/ 后重跑即可）：
/c/msys64/usr/bin/python tools/gen_article_codes.py
```

脚本会做**双源交叉验证**（98 版：yanhuacuo 表 vs CNMan 表的 98 列；新世纪版：WuBi06 库 vs WuBi 库的新世纪列），最近一次运行两版均 **0 处不一致**；86 版数据与 CNMan「旧86」列 185/186 一致（唯一例外「并」保留更通行的 UAG 拆分）。

脚本还会判定每字**末码的性质**（识别码 vs 字根）并写入 `id:1` 标志：98 版依据 yanhuacuo「字拆分表」的 15 种识别码标记（PUA 占位符，由全表 3 码字多数投票自行校准区位）；86 / 新世纪版在其基础上叠加「编码一致直传 + 末码区位几何校验」（末码字母 ≠ 该区位期望识别码字母则必为字根），另有 13 处人工裁定（`parse_codes.py` 内 `CORRECTIONS`，依据笔画覆盖关系与版本惯例差异——如 86 版规定 力/刀/戈 结尾字的末笔取折/撇，而 98 / 新世纪版取撇/点，导致 动、分、战 等字识别码跨版本不同）。

### 文章库与新增文章

文章源文件集中在项目根目录 `texts/` 下，**一篇一个 `.txt` 文件**（UTF-8，容忍 BOM）；`js/data/texts.js` 为生成文件，请勿直接编辑。

- 文件首个非空行 = 下拉列表显示名（如「曹刿论战 · 《左传》」），其余内容 = 正文；生成时自动去除换行与全部空白（文章走马灯为单行展示，正文中的空格也会被去掉）；
- 下拉顺序 = 文件名排序，文件名本身不参与显示；建议命名「两位数字前缀_短篇名」（如 `13_出师表.txt`），便于插入与排序；
- 生成脚本会逐篇报告字数，并检查正文每个汉字是否已有取码（练习字库 chars.js + 补充码表 codes.js），有缺字时提示再跑 `gen_article_codes.py`。

```bash
# 1. 新建 texts/13_出师表.txt：首行「出师表 · 诸葛亮」，其余粘贴正文
# 2. 重新生成文章库：
/c/msys64/usr/bin/python tools/gen_texts.py
# 3. 若上一步提示有未覆盖取码的汉字，重新生成补充码表：
/c/msys64/usr/bin/python tools/gen_article_codes.py
# 4. 刷新页面即可（index.html 与页面代码无需任何改动）
```

## 实现要点（开发约定）

- **零构建**：无打包器、无 npm 依赖；JS 为经典 `defer` 脚本按依赖顺序加载，禁止引入 ES module。
- **命名空间**：所有模块挂载于单一 `window.Wubi` 命名空间，按 `Wubi.data`（数据）/ `Wubi.core`（状态与逻辑）/ `Wubi.ui`（渲染）分层，各文件为 `'use strict'` IIFE。
- **版本切换链路**：`.tab[data-ver]` 点击 → `main.js` → `W.core.setVersion(ver)` → 清空两池并重建键盘、立即出题；数据面由 `W.data.ver` 驱动 `keys() / chars()`，选择持久化于 `localStorage['wubi_ver']`。
- **键盘尺寸**：键宽由 CSS 变量 `--kw` 控制，窄屏 / 触屏下改用容器查询单位 `calc((100cqw - 9*var(--gap))/10)` 等比撑满；`.wrap` 需保持 `min-width:0` 防止 flex 居中溢出。

## 回归自检（可选）

`tools/output/` 下附带两个无构建自检页（配合 headless Edge `--dump-dom` 使用）：

- `diag.html`：输出关键元素计算样式，验证窄屏布局无横向溢出；
- `diag_app.html`：真实点击切换版本 / 模式并断言出题、判题、讲解卡与持久化逻辑（最近一次 85/85 通过，含第 4 码识别码 / 字根分流与文章模式选篇同步 / 逐字推进 / 答错续输更正 / 篇末随机换篇 / 选篇从第一字开始与 ↺ 重开本篇 / 补充码表三版覆盖的回归断言）。

用法示例：

```bash
"/c/Program Files (x86)/Microsoft/Edge/Application/msedge.exe" \
  --headless=new --disable-gpu --window-size=1280,900 \
  --virtual-time-budget=4000 --dump-dom \
  "http://localhost:8000/tools/output/diag_app.html" | grep APPDIAG
```
